# 核心指标字典 v1

日期：2026-09-20。用途：在合并三份数据前，明确分析对象、指标含义与解释边界。

## 本期业务问题

识别哪些医院、哪些日期的入院等待持续偏长，观察它与急诊就诊量、床位占用率的变化有何关联，为运营团队提出需要进一步核查的环节。

入院等待指医生决定收治住院后，到患者离开急诊转往住院病房之间的时间。当前项目并不直接衡量初次见到医生的等待、所有急诊患者的总就诊时长或满意度。

## 三项指标及角色

| 指标 | 项目中的作用 | 官方说明支持的含义 | 暂时不能这样解释 |
|---|---|---|---|
| 每日入院等待时间中位数 | 主要结果指标：观察等待是否持续偏长 | 从医生决定住院到患者离开急诊、转往病房的等待，发布每日第 50 百分位数 | 不是平均数、所有急诊患者的总等待，也不能由中位数得到最长等待或长时间等待人数 |
| 每日急诊就诊量 | 需求背景指标：观察就诊需求变化 | 包括到急诊就诊的不同紧急程度患者；AH 对应 urgent care | 不能当作新增住院需求；所有急诊患者并非都要住院，也不能直接认定为跨日去重人数 |
| 每日床位占用率 BOR | 床位压力背景指标：观察统计时点的占用变化 | 按各医院午夜清点计算；官方所属日期 D 对应 D+1 日 00:00 | 不是全天平均或实时空床数；分子分母详细范围待 MOH 确认 |

三者角色是本项目的分析设计，不是 MOH 对因果关系的结论。需求、床位占用和等待可能共同变化，但不能仅凭共同变化就断言原因。

## 数据结构与待核项

当前已实现的分析粒度：一行是一家医院在一个官方所属日期的汇总数据，键为 hospital_code + date。不是患者级数据。

| 当前字段 | 说明 | 单位及检查要求 |
|---|---|---|
| hospital_code | 保留三份 MOH 原表一致的机构代码，没有自行改名 | 已核对九个代码一致；仍保留 NUH 成人范围、AH urgent care 与 WH 覆盖期的区别 |
| date | 原表所属日期 | 保留日期，不擅自把 BOR 日期整体后移一天 |
| admission_wait_p50_hours | 官方每日入院等待中位数 | 小时；2026-09-20 已视觉核对 MOH 对应图表标题中的 in Hrs，并比对当前周数值。原 Excel 本身未注明单位 |
| ed_attendances | 官方每日急诊就诊量 | 就诊计数；核对原表单位与整数特征，不解释成新增住院人数 |
| bor_ratio | 官方每日床位占用率的原始比例值 | 已核对非空源单元格为百分比格式。保留 0.95 等原值，在 Excel 按 95.0% 显示，不重复乘除 100；因此将原计划字段 bor_pct 明确为 bor_ratio |
| availability | 三项数值的可用状态 | 三项有值、仅床位占用率有值、三项无数值；有值不等于已证明口径完全可比或临床上正常 |
| ed_source / bor_source / wait_source | 对应原始文件的工作表及单元格地址 | 有源位置但数值为空，表示源单元格空白；源位置也为空，表示该来源没有对应日期医院记录 |

额外待核项：急诊量的日界线、跨午夜的入院等待记录按哪个事件日期归属、数据发布滞后，以及各序列定义在 2024—2026 年是否有变化。相同日期键便于合并，不意味着三项指标涉及完全相同的一批患者或同一时间窗口。

### 2026-09-20 三指标合并结果

按官方所属日期与原始医院代码执行一对一全外连接，保留任一来源出现的键，不移动 BOR 日期，不把缺失填成 0。研究期为 2024-01-01 至 2026-09-12。

合并表共 8874 行（986 日 × 9 个医院代码），其中 8637 行三项都有值，63 行只有 BOR 有值（急诊量和等待表缺失的 2026-08-02 至 08-08），174 行三项均为空（WH 的早期源单元格空白）。完整行数是医院日期记录数，不是患者数或独立样本数。

就诊量非空值均为整数。本期 BOR 非空原值范围为 0.486 至 1；没有观测到大于 100% 的值，但不据此设定日后清洗时一律删除超过 100% 的规则。分母详细范围仍待官方确认。

## 初版比较规则

1. 优先从同一家医院的历史变化开始，按星期几比较，减少医院规模与固定周内模式的干扰。
2. “偏长”先用历史基线探索；尚未确定阈值，不把个人项目阈值说成临床安全标准。
3. 每日中位数可以画趋势；它们的均值或中位数不等于全部患者的总体等待中位数。
4. 不把床位占用率低直接解释为运营效率高，也不把占用率高直接解释为管理差。
5. 发现异常后提出复核假设，如出院节奏、床型匹配、转运和人员配置；缺少相应数据时不能宣称已证明原因。

## 本次学习练习

教学假设：同一家医院，相比近几周相同星期几，急诊就诊量基本不变、BOR 降低，但入院等待中位数上升。

请先判断：等待问题是否值得关注？能否仅凭这三项数字确定原因？再提出一项最希望补充的信息，并说明它将帮助排除什么解释。

### 学习者回答摘要

以下为助手整理，非逐字引用：

- 认为该医院值得关注，尤其是占用率下降而入院等待中位数上升的组合。
- 提出可能是患者病情更轻、治疗或住院时间更短，并想到政策、当地医疗背景和患者构成可能有关。
- 怀疑分床、人员安排和院内协调存在延迟，希望补充入院过程的时间信息。
- 提及付款、确认床位、回家收拾物品及沟通等可能环节，但不确定哪些属于实际流程，也不确定应取哪些时间点。
- 原解释中将“急诊量基本不变”推到“急诊量不是占用率变化原因”，并将“占用率下降”理解为床位更容易安排；这两处需要纠正。

### 教师反馈：观察、假设与验证

1. 可以观察到的是三项指标的方向及其组合；值得进一步检查是否持续，仍不能仅凭这一组合确定原因。
2. 总急诊量不变，不能排除需求的影响。需要住院的比例、到达时段和所需床型仍可能变化。教学假设：两天均有 100 次急诊就诊，但分别有 10 人、30 人需要住院，总就诊量相同而住院需求不同。
3. BOR 下降不自动等于等待发生时存在更多适合该患者的床位。它还涉及原有住院患者、入出院节奏、可能的床位容量变化，以及午夜时点与等待发生时段不一致。详细床位分母仍待官方确认。
4. 病情更轻、住院时间缩短、人员或协调延迟都是待验证假设，不是由三项数据已经证明的结论。
5. 该项目研究的是急诊医生决定住院后至离开急诊转往病房。不能未经核实，把计划住院中可能出现的回家准备、预约报到等流程加入这项指标；付款是否发生在此区间、是否会阻塞转入病房，也需要院方流程或事件日志证明。

### 将“想补充时间信息”落实成字段需求

以下是拟向医院提出的院内事件数据需求，不是 MOH 现有三份公开表中的字段，也不声称已经确认具体医院采用这套流程。

| 字段 | 拟定含义 | 分析用途 |
|---|---|---|
| encounter_id | 脱敏后的本次就诊标识 | 将同一次就诊的事件连接起来；项目当前不请求或获取患者身份信息 |
| decision_to_admit_at | 医生决定住院的时点 | 对应官方等待区间起点 |
| allocated_bed_ready_at | 为该患者分配的合适床位已确认可接收的时点，须与院方统一事件定义 | 区分床位确认可接收前后的延迟 |
| exits_emd_at | 患者离开急诊、转往病房的时点 | 对应官方等待区间终点 |
| bed_request_at、bed_assigned_at、bed_ready_at | 可选的申请、分配及床位准备事件 | 如院内系统具备，可进一步分析分床、清洁或协调环节；实际流程可能并行，不能预设严格顺序 |

在这三个核心事件可比较、时间顺序正确且无缺失的患者记录中，可先将个人等待拆成：决定住院至床位确认可接收，以及床位确认可接收至离开急诊。后一段仍可能包含患者临床准备、交接、转运等因素，不能只凭时长确定人员不足。到达病房的时点可用于更广的流程分析，但不属于 MOH 这项等待指标的终点。

上述拆分应在个人就诊记录中计算。不能把两个阶段各自的中位数相加，冒充总等待中位数；更不能从目前的每日 P50 汇总值反推出这些阶段时长。

当前可执行范围：利用公开表识别值得复核的医院日和持续异常，形成待补数据与流程核查建议。没有院内事件数据时，不宣称已经定位到护士排班、缴费或转运瓶颈。

学习者已提出流程拆解与补充时间数据的思路；上述纠正与字段定义为教师反馈，尚未记录学习者修订后的复述。
